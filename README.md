# Riichicraft

面向 **Minecraft Java 26.2 / Fabric** 的日本麻将模组。

从一张能与朋友打麻将的桌子起步，逐步发展为包含自动麻将桌、完整牌具、NPC、特殊结构、独立维度和主线剧情的模组。

## 当前状态

已验证的游戏检查点为 **`v0.0.3` 四人摸打原型**：136 张牌含三赤五、东位开局、私人手牌、四家牌河、选牌后确认出牌和自动摸牌已实现。当前开发分支为 `0.0.4-dev`，先做不接入游戏的独立规则核心。

参与者掉线、死亡、跨维度或离桌太远会暂停并保留牌局；四人回桌后各自确认继续。关闭界面保留牌局，耗尽或二次确认终止后回大厅。破坏桌子、卸载区块或停服会终止临时牌局，本版不保存或恢复对局。当前游戏内不包含吃碰杠、立直、和牌或计分。详情见[摸打步骤](docs/DRAW_DISCARD.md)。

33 项服务端测试、真实客户端经 TCP 连接专用服务器的完整摸打与运行中断线重连检查已通过。接续位置见[接续记录](docs/SESSION_STATUS.md)，证据及验证边界见[验证记录](docs/VALIDATION.md)。

规则以雀魂普通四麻为准，包含一炮三响。独立核心已支持标准形／七对子／国士的完整分解与结构等待，以及普通役／役满、番符、宝牌和最高基础支付的单手分析。采用固定版本化预设：不切上满贯，13 番以上累计单倍封顶，四种特殊双倍役满可复合。

结构测试通过 168,715 个断言；计分测试通过 614 个断言、覆盖 45／45 项役枚举，均可脱离 Minecraft 运行。本批又加入振听历史与指定机会下的和牌检查：完整等待参与舍牌振听、同巡／立直见逃标志、自摸例外及国士抢暗杠限制，104 个新断言通过。

2026-10-16 用户进一步确认：无役一侧的结构完成牌也参与舍牌、同巡与立直振听。现由独立 `FuritenTracker` 根据响应前手牌，自动记录未荣和他家普通舍牌后的同巡／立直振听，不按有役或当前可荣和筛选；此项记录为用户裁定，新增 124 个断言通过。

计分与和牌检查仍须由未来对局引擎提供可信场况与真实机会；尚未生成完整动作历史或响应窗口，抢杠的独立见逃边界仍待核实，也未处理本场、立直棒、包牌、多人账本或整场结算。新核心尚未接入游戏，详情见[独立规则核心](docs/RULES_CORE.md)、[振听与和牌检查](docs/FURITEN.md)和[验证记录](docs/VALIDATION.md)。

已确定：

- 名称：Riichicraft；模组 ID 采用 `riichicraft`。
- 目标平台：Minecraft Java 26.2 / Fabric。
- 初期功能目标：三人／四人，东风战／半庄战。
- 交互方式：实体麻将桌＋手牌操作界面，优先保证清楚易用。
- 长期方向：独立维度、特殊结构与主线剧情。

## 开发与构建

Windows / PowerShell 7：

```powershell
./tools/Initialize-Dev.ps1
./tools/Check-Resources.ps1
./tools/Invoke-Gradle.ps1 build
```

首次运行会将固定版本 JDK、Gradle 和依赖下载到本项目。后续通过 `Invoke-Gradle.ps1` 使用项目专用环境，避免使用全局 Gradle 缓存。本开发分支产物为 `build/libs/riichicraft-0.0.4-dev.jar`，带 `-sources` 的文件是源码包；v0.0.3 检查点构建对应 `riichicraft-0.0.3.jar`。客户端与服务器都需安装同一版本的 Riichicraft 及兼容的 Fabric API；不同版本的网络协议不兼容。

只验证独立规则，不启动游戏或 Gradle：

```powershell
./tools/Test-Rules.ps1
```

```powershell
# 自动进入测试世界，验证客户端交互并保存截图
./tools/Invoke-Gradle.ps1 runClientGameTest

# 手动打开开发客户端
./tools/Invoke-Gradle.ps1 runClient
```

开发客户端里可以使用 `/give @s riichicraft:mahjong_table` 获得桌子，也可以在创造模式的功能方块分类中找到它。普通右键打开大厅，再点击“自动入座”；四人全部准备后，由东位开始摸打。潜行保留原版使用手持物品的行为。同一玩家只能占一桌，暂不提供 NPC 补位、坐姿动画和生存配方。大厅与牌局均为临时状态，桌子破坏、区块卸载或服务器停止时清理。
