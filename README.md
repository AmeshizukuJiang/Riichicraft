# Riichicraft

面向 **Minecraft Java 26.2 / Fabric** 的日本麻将模组。

从一张能与朋友打麻将的桌子起步，逐步发展为包含自动麻将桌、完整牌具、NPC、特殊结构、独立维度和主线剧情的模组。

## 当前状态

已发布的完整游戏开发检查点 **`v0.0.6-dev` 支持四人单局、东风、半庄及牌局存档恢复**。136 张牌含三赤五，私人手牌与公开牌河、吃碰杠、立直、自摸／荣和、流局及点数结算均可通过麻将桌界面操作。行动、牌河和结果支持分页，组合选择保留赤牌差异，食替与立直摸切由服务端限制。小局操作见[四人单局](docs/SINGLE_ROUND.md)，整场流程见[东风／半庄](docs/MATCHES.md)。

大厅由初始东位选择赛制，改赛制取消全员准备；四人准备后开始。新场每家25,000点，起家沿用初始东位。整场每小局结算后四人各自确认继续，保留点数／供托，按规则连庄／轮庄、递增本场、进入延长或最终排名。最终结果保留，任一参与者可带全桌返回大厅并取消准备；重新开场才重置点数。单局模式保留原来一次结算即返回的流程。当前没有三麻或NPC补位。

规则以雀魂普通四麻为基线，允许一炮三响，并如实标明用户直接裁定的边界，包括无役结构完成牌参与振听，以及流局满贯须门清（暗杠允许）。标准形／七对子／国士、役番符、宝牌、振听、抢杠与翻宝、流局及包牌均由独立核心裁决，服务端只发送本人私手和公开信息。详情见[四麻规则表](docs/FOUR_PLAYER_RULES.md)与[独立单局核心](docs/SINGLE_ROUND_CORE.md)。

活动局掉线、死亡、跨维度或离桌过远会暂停保留状态，四人回桌确认后继续。局间缺席清空续局票，返回后重新确认；关闭界面可重开，已结算点数不撤销。正常停服、自动保存与区块卸载会保存牌局；重新加载活动局后，原四人回桌确认继续，局间重新投续局票，终场保留结果。有效牌局破桌或主动终止仍清除。损坏档保留并禁止自动覆盖；异常崩溃最多恢复到最近成功保存，详情见[牌局存档](docs/PERSISTENCE.md)。没有长期点数账户。

20套独立测试共2,346,331项断言、42项Minecraft服务端测试与真实客户端TCP回归通过；保留完整东风／半庄回归，并实际停服、由新专用服务器实例重开同一世界，恢复部分已收响应后继续。核心归档另通过全新Java进程读写验证。证据与产物见[验证记录](docs/VALIDATION.md)。TCP配置为**一个真实客户端＋三名原生服务端内存夹具**，长摸打轨迹由服务端受控合法动作推进，不代表四真人验收。人工视觉与长期操作手感另行验证；接续位置见[SESSION_STATUS.md](docs/SESSION_STATUS.md)。

## 开发与构建

Windows / PowerShell 7：

```powershell
./tools/Initialize-Dev.ps1
./tools/Check-Resources.ps1
./tools/Invoke-Gradle.ps1 build
```

首次运行会将固定版本 JDK、Gradle 和依赖下载到本项目。后续通过 `Invoke-Gradle.ps1` 使用项目专用环境，避免使用全局 Gradle 缓存。当前开发产物为 `build/libs/riichicraft-0.0.7-dev.jar`，游戏仍只有四麻入口，三麻处于独立核心阶段；完整游戏检查点见`v0.0.6-dev`。带 `-sources` 的文件是源码包。v0.0.3历史检查点对应 `riichicraft-0.0.3.jar`。客户端与服务器都需安装同一版本的 Riichicraft 及兼容的 Fabric API；不同版本的网络协议不兼容。

只验证独立规则，不启动游戏或 Gradle：

```powershell
./tools/Test-Rules.ps1
```

```powershell
# 自动进入测试世界，验证客户端交互并保存截图
./tools/Invoke-Gradle.ps1 runClientGameTest

# 手动打开开发客户端
./tools/Invoke-Gradle.ps1 runClient
```

开发客户端里可以使用 `/give @s riichicraft:mahjong_table` 获得桌子，也可在创造模式功能方块分类中找到。普通右键打开大厅、自动入座；初始东位选择单局／东风／半庄，四人准备后由其点击“开始对局”。潜行保留原版使用手持物品的行为，同一玩家只能占一桌。具体鸣牌、立直与结算操作见[四人单局](docs/SINGLE_ROUND.md)和[整场说明](docs/MATCHES.md)。
