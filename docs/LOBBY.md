# v0.0.2 入座大厅

状态：2026-10-16 已实现，构建、14 项服务端测试、单人客户端与专用服务器 TCP／断线重连验证通过；详细证据和边界见 [VALIDATION.md](VALIDATION.md)。

## 本次玩家流程

1. 普通右键麻将桌，打开大厅界面。
2. 查看东、南、西、北四个逻辑座位；点击“自动入座”后由服务器按顺序分配第一个空位，显示占座玩家与准备状态。
3. 入座后可以准备／取消准备，也可以明确离座。
4. 关闭界面保留座位，重新右键可继续操作。断开连接释放座位。
5. 四名玩家全部准备后，提示“准备完成，配牌将在后续版本加入”。本步骤不设置会发出虚假开局反馈的开始按钮。

用户选择了自动分配座位，其余行为按方案确认。这里的风位仅用于大厅座位标识；起家与规则阶段的座次处理尚未确定。

本步不加入坐姿动画、手牌、发牌、麻将规则、三麻模式或 NPC。沿用现有普通桌模型与固定依赖。

## 实现边界

- 服务端独立维护每张桌子的大厅；一名玩家同时只能占一张桌子的一个座位。
- 客户端只提交入座、准备、取消、离座等意图，服务端确认玩家身份、桌子、座位和当前状态后决定结果。
- 每次开界面使用会话标识与状态版本；旧界面或重复请求不能重复推进状态。
- 界面从服务端快照刷新，不能将按钮显示的空位当作抢座成功的凭据。
- 公共／服务端代码不导入客户端类，界面和客户端网络接收放在独立源集。
- 大厅使用临时逻辑状态；完整对局的暂停、存档与恢复仍在 v0.0.5 实现，不能宣称此步骤已具备对局恢复能力。

桌子破坏、区块卸载和服务端停止时需清理尚未开局的大厅，防止幽灵占座。这些清理只针对本步骤的大厅，不能直接复用于未来已开局的牌局。

操作界面使用原版方块交互距离加 1 格容差。离开允许交互范围、死亡或切换维度会关闭该界面，保留大厅座位；重新靠近桌子可继续打开。没有自动离座倒计时。

## 验证目标

| 层次 | 检查 |
| --- | --- |
| 逻辑／服务端 | 两名玩家争同一座位只有一人成功；一个玩家不能占两桌；他人不能替别人准备／离座；旧请求不改变新状态 |
| 生命周期 | 关闭界面仍保留座位；明确离座／断线释放；破坏或卸载桌子后不残留大厅；两桌互不干扰 |
| 实际客户端 | 真正右键打开界面，通过按钮入座、准备、取消、离座，关闭后重新打开能同步；专用服务器 TCP 路径也执行 |
| 人工验收 | 中文可读、按钮清楚、提示符合实际；自动截图检查不能替代真人长期手感验收 |

上述自动检查的实际结果已写入 `docs/VALIDATION.md`。真人长期手感、多台真实客户端同时操作与实际区块卸载仍按验证记录标明边界。
