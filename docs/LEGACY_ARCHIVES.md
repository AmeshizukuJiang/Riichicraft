## 默认验证

[LegacyArchiveTests](../src/rulesTest/java/dev/riichicraft/rules/LegacyArchiveTests.java)在正常 `rulesTest` 中只读资源，要求：

1. 文件名集合、旧写入器和来源保持固定，各字节SHA匹配。
2. 新读取器成功恢复且重编码与原字节完全相同。
3. 显式公开／私有状态、牌山、点数和结果摘要相同。
4. 恢复整场不调用未来配牌工厂；已有响应和续局票不重复收取，供托不重复支付。
5. 旧版卡住的三拔北状态现在能实际摸切并到达正确荒牌结算。

Gradle默认从测试资源目录装载。独立 `tools/Test-Rules.ps1`将同一资源复制到本次项目临时类目录，从而保持不依赖Minecraft或全局测试库的运行方式。测试类、历史档案、生成器均不进入正式模组JAR。

## 重新核对来源时

日常测试**不重新生成**历史样本。需要核查时，先把上述精确旧JAR放在本仓库临时目录中，然后在仓库内执行：

```powershell
./tools/Generate-LegacyArchives.ps1 -BaselineJar '.tmp/audit-fixes/baseline-v16.jar'
```

脚本默认写入一个新的项目临时目录，任何非空目标目录都会被拒绝。输出应与固定目录的14个二进制及manifest逐项字节一致。本轮已独立执行这项比较，15个资源全部一致。旧JAR仅本地参考，不随模组或仓库分发。

开发阶段若修改规则语义或档案格式，应记录当前格式及测试变化，可替换不再适用的历史样本；无需为了旧测试版增加迁移代码。仍然适用的规则和错误处理断言应保留，避免把实际回归误当格式调整。正式发布后的兼容策略待完整模组形成后再设计。
