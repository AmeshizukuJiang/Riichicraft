# 第一个开发步骤：v0.0.1 工程与基础麻将桌

状态：基础功能已实现，已完成自动构建和游戏内验证；2026-10-16 已继续开发入座大厅，见 [LOBBY.md](LOBBY.md)。具体证据与验证边界见 [VALIDATION.md](VALIDATION.md)。本文件的清单保留为基础桌步骤的范围说明。

## 玩家可见结果

启动 Minecraft Java 26.2 / Fabric 后，能够找到 Riichicraft 的麻将桌物品，将其放进世界，看到有方向的简化桌子，右键得到明确的基础交互反馈，破坏后获得正确掉落。

这一步交付一个可以检查的模组起点。入座大厅、配牌和麻将规则从后续步骤逐个加入。

## 实现清单

1. 基于官方 Fabric 模板创建工程，目标版本固定为 26.2。
2. 核对并锁定 JDK、Gradle Wrapper、Loom、Loader、Fabric API 的兼容组合，记录构建与运行方式。
3. 设置名称 `Riichicraft`、模组 ID `riichicraft`；Java 包名在工程创建时确定并记录。
4. 将客户端渲染入口与公共／服务端代码分开，保证专用服务器可加载。
5. 注册 `riichicraft:mahjong_table` 方块及物品，添加简化模型、材质、方向、中文／英文名称和掉落。
6. 右键反馈桌子当前处于“基础桌原型”状态，不显示尚未实现的开局功能。
7. 补充 README：依赖版本、构建步骤、测试方式、产物位置与本次限制。

模型先采用简单方块方案。成品桌的尺寸、多方块结构、座椅和三维摆牌在相应阶段设计。生存合成配方随生存体验阶段加入；本步骤通过创造物品栏或开发命令获得桌子。

## 完成标准

| 检查 | 通过条件 |
| --- | --- |
| 构建 | 使用项目 Wrapper 能生成模组 jar |
| 客户端启动 | 目标 26.2 环境可进入世界，没有缺失模型／材质／翻译 |
| 放置与朝向 | 在不同朝向放置后，方向和碰撞行为符合设计 |

| 专用服务器 | 同一版本组合启动并能让安装相同模组的客户端加入、交互 |
| 记录 | 列出实际执行过的检查及结果；未实测项目明确标记 |

已执行构建、服务端 GameTest、单人客户端测试和本地专用服务器连接测试；人工长期体验与正式启动器安装验收尚未开展。
