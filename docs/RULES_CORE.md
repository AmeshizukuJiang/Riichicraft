# 独立四麻规则核心

开发版本：`0.0.4-dev`。已有牌形／等待、单手役符、振听／舍牌及抢杠见逃、两类响应、鸣牌／弃牌、牌山、立直／一发、小局账本和翻宝／第四杠门槛；现已由 `FourPlayerRound` 串联真实阶段、公开／私有视图、流局及包牌来源，形成独立单局。Minecraft 适配正在进行，尚不能宣称游戏验证完成；整场四麻与三麻仍未实现。

用户已确认以雀魂普通四麻为规则基线，允许一炮三响。来源、已修正差异及后续待核实项见 [FOUR_PLAYER_RULES.md](FOUR_PLAYER_RULES.md)。

## 当前代码边界

| 文件 | 职责 |
| --- | --- |
| `Meld` | 已声明吃、碰、开放杠、暗杠；使用唯一物理牌 ID，验证牌组结构与防御拷贝 |
| `HandInput` | 手牌及声明组；验证物理牌不重复、数量与杠数、牌种上限，区分 13／14 张结构状态及门清 |
| `HandDecomposition` | 使用牌种表示标准形的雀头和四组面子、七个对子或国士重复牌；固定副露不会被拆开重组 |
| `HandAnalyzer` | 返回所有不同的标准分解及七对子／国士解释；对 13 张结构状态返回可补的牌种集合 |
| `WinContext` | 和牌方式、物理和牌张、自风／场风、立直／一发、牌源／首摸事件及表／里指示牌；校验输入的一致性 |
| `WinInterpreter`／`WinningInterpretation` | 在每种完整结构中枚举和牌张归属及两面、边张、嵌张、单骑、双碰等解释；不将固定副露拆开重组 |
| `Yaku`／`YakuAward` | 普通役与役满的名称，以及该解释取得的番数或役满单位 |
| `HandScorer` | 排除无役解释；计算普通役、役满、宝牌并枚举择优，返回全部或最高基本支付的解释 |
| `FuCalculator` | 按选定解释计算符及明细；处理平和、七对子、荣和补刻、连风和最低符例外 |
| `PointCalculator` | 根据已成立的役符计算基本点、上限和庄／闲荣和／自摸支付，不负责裁决可和性 |
| `ScoreResult` | 保存选定解释、实际采用的和牌张、役、番符、宝牌数量、役满单位、符明细与基础支付 |
| `FourPlayerRules` | 固定、带版本的普通四麻计分预设；当前 ID 为 `riichicraft:four_player_v1`，revision 为 `1`，不是玩家可切换的配置选项 |
| `FuritenState`／`FuritenAnalyzer` | 保留本局历史舍牌、同巡／立直见逃标志，用完整结构等待重算舍牌振听；只由本人真实摸牌清除同巡标志 |
| `FuritenTracker` | 响应前手牌的普通舍牌／抢杠见逃；普通舍牌及加杠按全部结构完成，暗杠仅国士完成记录，不建立对局或网络授权 |
| `WinEvaluator` | 在调用方提供的真实机会下，检查牌形、有役、振听、抢杠来源及国士抢暗杠限制；返回手牌价值和明确拒绝原因 |
| `DiscardResponseWindow` | 收集一次普通舍牌的三家响应，校验窗口和具体动作选择，按优先级保留全部荣和赢家并生成见逃历史结果；具体合法鸣牌选项仍由动作层提供 |
| `CallActions` | 根据可信座位／牌山／杠数／立直事实生成吃碰明杠的准确物理选项，检查食替并执行不可变手牌移组；保留提供者及立即弃牌／岭上补牌约束 |
| `RoundWall` | 可复现配牌、活牌和王牌；普通／末张／岭上来源、四次岭上与活牌尾补入王牌；指示牌槽位与私有诊断，不负责翻牌时序 |
| `DiscardActions` | 摸牌后准确实体弃牌、立直摸切锁、吃碰后按食替遮罩出牌；更新历史但不自行清同巡 |
| `RiichiState` | 立直候选、宣言待响应／成立分离、准确窗口绑定、双立直与一发时序；输出待记账扣点／供托 |
| `RoundLedger` | 将立直结果记入真实小局账本，荣和／自摸、本场／供托和可信组件包牌支付；荒牌／流满／途中流局结算、供托保留、100,000 守恒和重复支付拒绝 |
| `KanActions` | 暗杠／加杠物理选择、立直等待与送杠限制；产生响应前、无抢杠成立、被抢减一枚的私有手牌快照 |
| `KanResponseWindow` | 三家抢杠／跳过，核对四家物理身份与已有杠数，保留多响并生成来源特定的见逃历史和宣言者手牌结果 |
| `KanRoundState` | 四家杠归属、立即／延后／连续翻宝、岭上回合座位和准确第四杠舍牌门槛；不替代统一对局阶段 |
| `RoundDrawRules` | 形式听牌、九种九牌、四风与门清流满资格；按先前声明组和最后真实鸣牌来源建立包牌责任 |
| `FourPlayerRound` | 单线程四麻单局权威；UUID 身份、阶段与修订、稳定响应窗、唯一手牌／牌山／账本、私有视图、真实规则事件、终局及每步整副牌与点数守恒 |

文件位于 `src/main/java/dev/riichicraft/rules/`。仅复用纯 Java 的 `game/TileCatalog`，不引用 Minecraft、Fabric 或第三方规则库。

输入牌 ID 为 0～135，牌种为 `ID / 4`；赤五的结构等同普通五，计分使用原物理 ID 识别赤宝牌。声明杠占一组面子，完整手实际牌数为 14＋杠数；即使暗杠保持门清，也不再允许七对子或国士。

`HandInput.isComplete()` 只表示 14 张结构数量，`isWaiting()` 只表示 13 张结构数量，均不是和牌／听牌合法性结论。真正结构完成由 `HandAnalyzer.analyze()` 的非空结果表示。

`waits()` 不考虑公开牌河、牌山中还剩几枚、役或振听；全手（含声明组）已经持有四枚的牌种不会被返回。形式听牌现由独立入口 `RoundDrawRules.tenpai()` 裁决：按用户确认，无役、振听与外部待牌见尽仍算听，自持四枚只能求第五枚不算听；统一单局在真实荒牌窗口使用该入口。

## 单手计分输入与结果

`HandScorer.score(hand, context)` 接受完整的 `HandInput` 和可信的 `WinContext` 场况事实。和牌张必须是完整暗手中真实存在的物理牌，已声明组和指示牌同样保留物理身份；输入会检查牌重复、牌数、牌种上限、门清与立直的一致性，以及事件与荣和／自摸方式是否相容。空指示牌列表允许孤立的手牌价值分析；以后真实对局须提供其实际指示牌。

**这个接口计算手牌价值，不授予和牌权限。** 它不读取或修改玩家、牌山、牌河、网络及历史状态，也不裁决舍牌／同巡／立直振听、立直是否成功成立、一发是否已被打断、首摸是否受鸣牌影响、最后一张的真实牌源，或当前是否处于可和／抢杠窗口。这些事实现由 `FourPlayerRound` 根据实际历史建立，不能让客户端自行声明后直接结算。

`score()` 返回最高基础支付的合法计分解释；`scoreAll()` 返回按所得基础支付降序排列的全部计分解释。标准形、七对子、国士及具体和牌张归属分别判断，不以第一个分解或最高番数直接代替最高实际得点。没有普通役的结构不会仅靠宝牌、赤宝牌或里宝牌变成可计分和牌；返回空结果也不等同于振听判定。

当前单手计分包括：

- 普通四麻的全部普通役与役满，以及门清／食下、暗刻与荣和补刻、互相替代的役等关系。
- 普通宝牌、赤宝牌、立直时的里宝牌和重复指示牌累计。真役满按役满单位复合，排除普通役与宝牌；国士十三面、四暗刻单骑、纯正九莲、大四喜各为双倍。
- 符明细、逐家向上到百点的基础支付、不切上满贯、13 番及以上累计单倍役满封顶。基础支付不包含本场、立直供托、包牌、同时多家荣和或全局点数账本。
- 明确的 `TENHOU` 天和上下文允许在初始 14 枚中枚举最有利的和牌张指定，采用最高基础支付；普通和牌及地和保留实际和牌张，不能任意改指定。

`PointCalculator` 是较低层的数值计算器，调用者必须先保证有役等前提；直接传入番符不能证明该手牌在当前历史中可和。统一单局现已接续机会检查、状态机与小局账本，整场结算另做。

## 振听与指定机会下的和牌检查

`WinEvaluator` 接续计分核心：荣和时移除准确物理和牌张，以此前全部结构等待和历史舍牌取交集，并检查同巡／立直见逃；自摸跳过振听限制，但仍检查牌形和役。抢暗杠只允许国士；两类抢杠均检查该类型不能再出现在赢家其他牌或表／里指示牌中，避免第五枚。

`Decision.handValue()` 可在振听否决时保留计分解释，调用方必须检查 `allowed()`。此结果仍不是完整网络授权：实际机会、行动者、立直成立和其他历史事实现由统一单局建立；`WinEvaluator` 本身不主动产生见逃、开窗口或执行支付，连接认证仍归适配层。

普通舍牌的见逃由 `FuritenTracker.afterDiscardWithoutRon(waitingHand, discardedTileId, history, establishedRiichi)` 处理：使用响应前、吃碰前的 13 张结构手牌；该物理舍牌可完成结构便按已成立立直状态记录同巡／立直振听，非完成牌保持历史。它不筛选役、宝牌或 `allowed()`；不能用于本人舍牌、摸牌或抢杠，也不建立行动者、响应窗口、局号或防重放机制。无役一侧也触发振听是 **2026-10-16 用户直接确认**，并非新取得的官方原文。例子及其他边界见 [FURITEN.md](FURITEN.md)。

`DiscardResponseWindow` 已接续普通舍牌这一步：内部推导荣和选项，没有动作的玩家自动跳过；收齐三家选择后保留所有荣和者，或选碰／大明杠优先于吃的鸣牌，输出三家见逃历史。其他家先响应不使本家窗口 ID 过期；错误局号／窗口号、重复和未提供动作不会改变结果。此窗口只接收可信动作层提供的具体鸣牌选项，没有生成完整合法动作、执行牌移动或结算。契约见 [DISCARD_RESPONSES.md](DISCARD_RESPONSES.md)。

## 独立验证方式

使用项目内固定 JDK，直接编译和运行，不启动 Gradle、Fabric 或 Minecraft：

```powershell
./tools/Test-Rules.ps1
```

脚本只编译 `rules/`、`TileCatalog.java` 与 `src/rulesTest/java/`，使用每次新建的空类路径；产物只写入忽略的 `.tmp/rules-tests-*/`。所有断言显式失败即非零退出，不依赖全局测试框架。

也可通过项目构建执行：

```powershell
./tools/Invoke-Gradle.ps1 rulesTest
./tools/Invoke-Gradle.ps1 build
```

`rulesCore`／`rulesTest` 为独立 source set，测试进程没有 Minecraft 或 Fabric 依赖；`check` 包含此测试。正式模组仍由 `main`／`client` 打包，测试类不随模组发布。

已执行的次数、样本数和结果以 [VALIDATION.md](VALIDATION.md) 为准；新增测试入口本身不等于已通过。

结构批次已通过 **168,715 个断言**。单手计分批次已通过 **614 个断言**，覆盖 **45／45 项役枚举**，并核验番符、特殊双倍、宝牌、拆解择优和输入边界；详细验证范围见验证记录。该批役枚举覆盖本身不证明历史状态机；后续单局另有整局验证，均不替代接入游戏的验证。

振听原语与指定机会检查另有 **104 个断言**通过，涵盖有役不对称等待、状态清除、自摸仍须有役、抢杠与赤五／指示牌的物理约束、输入错误和结果不可变。

普通舍牌见逃自动记录新增 **124 个断言**通过，覆盖用户确认的无役边界、先见逃再碰牌的物理事件链、实际摸切后恢复、立直／双立直、特殊形、多拆解、赤牌与调用前提检查。

普通弃牌响应窗口新增 **5,224 个断言**通过，覆盖三响、响应顺序独立、座位轮换、动作优先级、自动跳过与见逃、请求重放和物理牌选择。

鸣牌动作新增 **43,462 个断言**，牌山新增 **101,983 个断言**，包含物理组合参考对照、赤牌、食替、末次禁鸣牌、鸣牌手牌执行，以及混合摸牌下完整 136 枚身份守恒，见 [CALL_ACTIONS.md](CALL_ACTIONS.md)。

弃牌新增 **9,202 个断言**，立直新增 **325 个断言**，账本新增 **3,201 个断言**，覆盖实体摸切锁、宣言窗口与多响取消、一发、实际扣棒、基本和牌及多响／组件责任账单。见 [RIICHI_AND_LEDGER.md](RIICHI_AND_LEDGER.md)。

杠动作批次为 **5,205**、抢杠响应 **8,149**、翻宝／第四杠与组合场景 **7,169** 个断言。覆盖全牌种与物理选择、立直合法拆解变化、384 个抢杠响应场景、512 个第四杠归属／来源场景，以及连续四暗杠的真实配牌／岭上／计分／账本组合，见 [KAN_FLOW.md](KAN_FLOW.md)。以上十三套共 **353,477 个断言**。

统一单局新增 `RoundDrawTests` **103,218**、`FourPlayerRoundTests` **1,119,055**、`RoundScenarioTests` **538** 个断言，十六套共 **1,576,288**。64 个固定种子轨迹实际全部荒牌，包含 259 次鸣牌、8 次杠、零立直／和牌；12 个完整确定墙场景补充真实双响／三响、立直、抢杠、岭上、包牌和流满等事件。范围与局限见 [SINGLE_ROUND_CORE.md](SINGLE_ROUND_CORE.md)，统一重跑及构建结果以验证记录为准。

## 后续顺序

统一单局、形式听牌与各类流局、流满结算、责任触发历史及每步守恒现已实现，见 [SINGLE_ROUND_CORE.md](SINGLE_ROUND_CORE.md)。接下来重点是游戏适配与实际服务端／客户端验证；整场轮转、目标点／末局停止、最终排名及三麻仍在后续范围。

原 v0.0.3 的联网摸打、暂停及重连是此前已验证的游戏基线；本轮正接入新规则接口和动作，尚未完成的新流程不沿用旧验证结论。

用户已授权核心形成可验证闭环后由代理直接接入游戏；不再为接入时机本身重复等待确认。规则与网络裁决必须先具备可靠的阶段、私有视图和准确结算，接入后的服务端／客户端与人工体验仍分别报告。
