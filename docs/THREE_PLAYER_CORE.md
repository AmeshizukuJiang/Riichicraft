## 已实现范围

| 接口 | 当前契约 |
| --- | --- |
| `ThreePlayerRules` | 固定三麻预设ID／修订，3席、108牌／27种、35,000起返／40,000目标 |
| `ThreePlayerTiles` | 保留原0～135物理ID，删去2～8万，不重新编号成0～107；不可变牌池；严格类型／赤牌检查；1万↔9万宝牌、风牌仍含北 |
| `PointCalculator.basicValue` | 抽出两份固定预设共用的番符／上限计算，不先建立四麻账单；不切上满贯、13番累计单倍、真实役满单位 |
| `ThreePlayerPointCalculator` | 已给定合法和牌价值的基础支付：荣和不变，闲自摸只向庄和另一闲家、庄自摸只向两闲家收费，逐个付款家取整到百点 |
| `ThreePlayerWinContext` | 包装通用和牌事实，附本人已成立的北物理ID及`NONE／SUPPLEMENT／ROBBERY`事件；拒绝北席／北场、移除牌、重复北及指示牌冲突 |
| `ThreePlayerHandScorer` | 枚举完整手牌的全部解释，复用共有役符，单独累计三麻表／赤／里／拔北番，再按真实三麻支付选最高得点 |
| `ThreePlayerScoreResult` | 单独的三麻支付类型和`dora／aka／ura／kita`明细；不改变四麻结果或旧归档格式 |

`ThreePlayerPointCalculator`的`Payment.fromNonDealer`在闲家自摸时收一次，庄家自摸时收两次，与旧四麻DTO含义不同，因此使用独立类型。没有先算四麻总额再乘比例，也不从虚拟北家扣款。

基础金额入口只计算金额，**调用者必须已经保证和牌合法且有役**；不会根据番符判断手牌、振听或事件资格。尚未纳入本场、供托、多响、责任、流满与不听罚符。三麻手牌使用`ThreePlayerHandScorer`，不要直接把三麻万子指示或拔北数交给四麻`HandScorer`。

基础值与真实付款分别检查整数范围。一个三麻自摸账单若可以用int表示，不应因为不存在的第三付款家或当前用不到的荣和数额会溢出而被误拒；新测试覆盖可表示的最大三麻庄／闲自摸，以及刚好超过边界的拒绝。四麻`calculate`继续使用同一基础值建立三付款家账单，原有结果与归档字节稳定性回归保留。

## 手牌计分与北的三种身份

- **留在手中**：北是普通字牌，不能作为自风／场风役；可组成对子、刻杠、七对子或国士。北对子不加役牌雀头符，刻杠照字牌算符，不增加拔北番。
- **本人已成立的拔北**：从手牌之外提供准确物理ID，既不占面子也不添符、不破门清，每枚增加1番拔北奖励。西指示的北宝牌同时数手内、声明组及已拔北，重复指示逐次累计；里宝仅已立直有效。无役不能被表／赤／里／拔北救活。
- **被抢的北**：作为荣和牌放入赢家完成手牌；不能把该次未成立的拔北加入赢家拔北区。`ROBBERY`不自动增加抢杠役，可保留此前有效一发。普通形、七对子、国士都可分析，但仍须实际有役及不振听。

`SUPPLEMENT`以通用`NORMAL`自摸事实输入，再单独增加岭上开花；不虚构一个杠、不绕过四麻“岭上需声明杠”的原校验。至少存在一枚本人已成立北，不允许叠一发、海底或首巡役满；先前已成立的双立直可以保留。正常开杠补牌仍用通用`RINSHAN`和真实声明杠。两类补牌都只增加一次岭上役，真实役满优先，全部普通役、宝牌及拔北番归零。

手内／声明组／拔北／表里指示不能复用同一枚物理牌；拒绝二至八万、吃组、未完成手牌和不在暗手中的和牌。已拔北不加入结构分析，因此不会替手牌补足北对子或国士；完整等待与自持四枚限制将在等待／事件适配时接入。

按每个解释的三麻实际两付款家金额排序，不先选四麻最高结果再换算。天和沿用已确认的最优和牌枚解释，地和固定实际摸牌；四麻役种／符数算法只抽出不含宝牌、支付的内部解释，未改旧公开计分结果或归档契约。

这仍是**手牌价值分析，不是合法动作裁决**：调用方负责实际抢北／补牌窗口、此前有效一发、立直／首巡历史、振听和当前有效指示。已确认“拔北不提前翻延后杠宝”将在牌山／事件引擎执行；此处只统计传入的有效指示，不自行翻牌。

## 验证

牌池／基础支付首批独立21套、2,352,539项断言通过，其中`ThreePlayerBasicsTests`为6,208项，原20套不排除。基础套件包含：

- 全136共享ID的合法／移除分类、每种四枚、保留真实赤牌身份、非法／越界拒绝及不可变集合。
- 全108枚指示牌的独立映射表、1万／9万、筒索9回1、东南西北四风循环及三元循环；四麻1万仍指2万。
- 29行独立番符／庄闲／荣自摸基础支付表，30种番数×15种符数×两种庄闲×两种和法矩阵，真实役满1～8单位，逐家取整及欠一付款家关系。
- 高番累计封顶、不切上两条边界，非法番符／负数、真实支付整数边界及“仅不存在的四麻付款溢出”的三麻可接受情况。

固定番符表是算术入口测试，不声称每一番符／和法组合都有对应合法手牌。全套核心归档测试仍另启动全新Java进程验证旧四麻恢复；不能说它验证了尚未实现的三麻存档。

第二批`ThreePlayerScoringTests`新增1,880项，完整独立22套、2,354,419断言通过：固定三麻番符与支付、北对子／刻杠、无杠拔北岭上、普通形／七对子／国士抢北及一发、两赤和杠四枚宝牌、西表里叠加、无役及真实／累计役满、天和最优解释、全部92个可用物理指示牌矩阵、三席×三场风×荣自摸×物理副本变换的共用役符回归，以及非法输入和不可变集合。共用役符比较是回归证据，固定独立例与算术表是独立预期；不把两者都称外部规则引擎交叉验证。

最终离线完整构建1分10秒通过，22套2,354,422断言（Gradle多3个项目内类路径检查），现有四麻／存档42项required服务端回归12.35秒全过；资源、文档和jar检查通过，Gradle daemon已停止。产物及日志见 [VALIDATION.md](VALIDATION.md)。没有三麻GameTest或客户端三麻开局，不把当前独立组件称为真实三麻对局已完成。
