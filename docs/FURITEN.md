# 振听状态与指定机会下的和牌检查

版本：`0.0.4-dev`。本批仍为独立 Java 核心，没有接入游戏界面、网络或完整对局状态机。普通舍牌已另有 [响应收集与裁决窗口](DISCARD_RESPONSES.md)，收齐选择后使用本节接口生成见逃历史；雀魂规则依据见 [FOUR_PLAYER_RULES.md](FOUR_PLAYER_RULES.md)，验证结果见 [VALIDATION.md](VALIDATION.md)。

## 职责

| 接口 | 输入与作用 |
| --- | --- |
| `FuritenState` | 一名玩家在本局的历史舍牌种类、同巡见逃标志及立直见逃标志；不可变，可由后续可信对局层保存 |
| `afterDiscard(physicalTileId)` | 记录真实舍牌的牌种；赤五和普通五属于同种。被他家鸣走的舍牌也保留；杠宣言不能调用此方法 |
| `afterDraw()` | 本人实际摸牌时清除同巡标志，保留立直见逃与历史舍牌；吃碰、弃牌或别家摸牌不能以此代替 |
| `afterPassedRon(establishedRiichi)` | 对局层已经确认发生见逃触发事件后，按立直是否已经成立，记录同巡或本局持续的立直振听；本方法不裁决立直成立窗口 |
| `FuritenTracker.afterDiscardWithoutRon(waitingHand, discardedTileId, history, establishedRiichi)` | 一名玩家未荣和他家普通舍牌后，用响应前的 13 张结构手牌判断该物理舍牌能否完成牌形；能完成就记录同巡／立直振听，否则保持历史，不筛选役或宝牌 |
| `FuritenAnalyzer.evaluate(waitingHand, history)` | 对十三张结构状态计算全部结构等待及与历史舍牌的交集；不以有役等待筛选，不检查外部已见牌和牌山库存 |
| `WinEvaluator.evaluate(completedHand, context, history, source)` | 在可信调用方给定的自摸、舍牌、加杠或暗杠机会下，检查牌形、有役、振听与抢暗杠限制，返回手牌价值及明确拒绝原因 |

舍牌振听每次按当前等待重新计算。曾经舍弃过某种牌不是永久禁止荣和；改成与全部历史舍牌不相交的等待后，这一原因消失。只要当前任一结构等待曾被本人舍弃，其他等待同样不能荣和，包括这一侧有役而另一侧没有役的情况。

同巡与立直见逃是单独的历史标志。手牌变化和当前等待改变不会自行清除同巡标志；本人下一次真实摸牌才清除它。立直见逃不因摸牌清除。所有振听只限制荣和与抢杠，自摸仍须正常检查牌形和役。

## 无役一侧同样触发振听

**2026-10-16 用户直接确认**：无役的结构完成牌同样参与舍牌、同巡和立直振听。此项按用户裁定落实，不声称找到了新的雀魂官方原文。

例如 `123m 456p 789s EE WW`（E＝东、W＝西），设东为役牌、西非役牌且无其他事件役：听东、西双碰，荣和东有役，荣和西无役。本人曾舍弃西，东、西均不能荣和；尚未立直时放过他家舍出的西，在本人下次摸牌前也不能荣和东。已成立立直后放过任一结构完成牌，则本局持续振听；立直本身提供役，不改变按全部结构等待判定的原则。

`FuritenTracker` 自动处理的是**这名玩家未荣和他家普通舍牌**这一事件，不能以 `HandScorer` 是否有结果或 `WinEvaluator.allowed()` 是否为真筛选触发。必须传入吃碰等响应改变手牌之前的 13 张结构状态；即使这次舍牌随后被吃碰，也应先处理见逃，再改变手牌。该接口只生成振听历史，不证明行动者、对局或响应窗口真实有效，不建立局号、修订号或防重放机制。抢杠不得调用此普通舍牌接口；本人舍牌与摸牌仍分别调用 `afterDiscard()`、`afterDraw()`。

## 和牌检查结果

`WinEvaluator.Decision.handValue()` 是单手计分解释。即使因振听禁止荣和，该值也可能存在；调用方必须检查 `allowed()`，不能只看有没有分数。结果不修改手牌、历史或点数，不隐式记录见逃，也不执行支付。

正常规则否决以 `Rejection` 表示：牌形未完成、无役、舍牌振听、同巡振听、立直振听、抢暗杠要求国士。可同时保留多项原因。十三张直接作为完成手输入、和牌张物理身份错误、机会来源与场况冲突等调用前提错误则抛出异常。

荣和检查从完整暗手移除**指定的物理和牌张**，再分析此前的全部等待。不能删除另一枚同种牌，也不能用计分结果中更有利的拆解缩小振听范围。

舍牌来源必须是正常荣和或河底；加杠／暗杠来源必须使用抢杠场况。抢暗杠仅接受国士无双，抢加杠仍正常检查有役与振听。声明者持有该类型的四枚，故赢家完整手中只能出现和牌张这一枚同种牌，表／里指示牌也不能含同种牌；否则需要第五枚，属于输入前提矛盾。国士十三面抢暗杠因这一物理限制不能成立。

## 本批边界

- 调用方仍须建立真正的对局、行动者和响应窗口，验证被抢杠者持牌，生成可信的立直、一发、首摸和牌源事实。本接口本身不能作为客户端和牌包的完整授权检查。
- 普通舍牌的结构完成见逃已由 `FuritenTracker` 自动记录，包括无役及已经因振听而不能荣和的情况；调用方仍负责确认确实未荣和，以及提供响应前手牌和当时已成立的立直状态。
- 本人下次摸牌解除同巡振听来自雀魂 FAQ id44；岭上按这一一般表述处理，未另找到独立专条。暗杠非国士完成牌被跳过的自动触发分支也未取得明确依据，不自行补规则。
- 普通舍牌响应收集与优先级裁决已有独立窗口；尚无立直宣言／成立、完整鸣牌动作生成及执行、抢杠窗口、超时策略、整局牌守恒、多人支付、形式听牌及本场／供托／包牌结算。三麻不在本批范围。
- 这些接口没有修改现有 v0.0.3 摸打、暂停或重连流程。本批无需用户实机验收，不能据此声称新规则已经在 Minecraft 对局中运行。
