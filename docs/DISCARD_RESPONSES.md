# 独立弃牌响应窗口

版本：`0.0.4-dev`。`DiscardResponseWindow` 管理四麻一次普通舍牌的响应收集、优先级裁决和见逃历史结果，未接入 Minecraft。规则沿用 [FOUR_PLAYER_RULES.md](FOUR_PLAYER_RULES.md) 的荣和＞碰／大明杠＞吃、双响／三响与用户确认的无役见逃规则。

## 输入与责任

构造窗口需要 `Id(roundId, serial)`、出牌座位、物理舍牌，以及另外三家的 `Participant` 快照。座位 `0..3` 按摸打顺序递增，吃只允许出牌者之后的一家；桌位与当局自风分开，不假设桌位永远等于自风。

每家提供响应前的十三张结构手牌、荣和场况、原振听历史及可信动作层已核准的 `Call` 集合。窗口通过现有 `WinEvaluator` 自行决定能否荣和，不接受调用方直接声称“能荣和”。吃／碰传入两枚、明杠传入三枚本人暗手中的准确物理牌，不包括舍牌；牌组按 ID 规范排序，赤牌选择保留。

窗口重新检查座位、牌数、牌组结构、暗手所有权、吃的方向、已成立立直不能吃碰明杠。三家手牌／声明组、舍牌及共有表里指示牌不能重复占用同一物理牌；各家须使用同一真实舍牌、场风、牌源事件和指示牌，各自自风互不重复。这是当前快照的局部守恒，不等于已核对完整 136 张牌山、牌河和出牌者余牌。

食替、末次鸣牌、剩余牌山与可杠次数等检查现由独立 `CallActions.options()` 提供，具体契约见 [CALL_ACTIONS.md](CALL_ACTIONS.md)。窗口本身仍不生成这些选项；未来对局拥有者须使用实际阶段、牌山和已成立杠／立直事实调用，不能信任客户端声称的事实或选项。`Participant` 及完整场况是服务端私有数据，不能作为广播给其他玩家的网络视图。

## 收集与裁决

1. 自动加入 `PASS`；只有 `WinEvaluator.allowed()` 为真才加入 `RON`，再加已核准的具体吃碰杠选项。
2. 只有 `PASS` 的玩家自动完成响应，包含无役或已振听、又没有可选鸣牌的玩家；不会要求他们对不存在的按钮额外操作。
3. 有选项的玩家通过 `submit(expectedWindow, seat, choice)` 提交一次选择。轮到哪家先收到网络包不改变优先级，也不让其他家已获发的窗口 ID 失效。
4. 三家全部完成响应后才生成一次 `Resolution`。任何已选择荣和的玩家均保留，按出牌者之后的摸打顺序排列；不头跳，也不把三响改为流局。无荣和时，已选择的碰／大明杠优先于吃；仅有一个高优先级选项但玩家选择跳过，不会占用优先级。
5. 选择荣和者保留原历史；其他玩家以响应前手牌调用 `FuritenTracker`，自动记录结构完成见逃，包含无役、已有振听及选择吃碰的情况。即使选择的鸣牌被更高优先级覆盖，也不会抹去本人放过完成牌的事实。

`Resolution` 返回无声明／荣和／鸣牌结果、所有赢家及各自基础手牌价值、选中的准确鸣牌组合，以及三家更新后的振听历史。它不扣分、不加本场／供托、不移动牌、不执行鸣牌后的弃牌或岭上摸牌，也不自动推进下一摸。多人荣和共享原舍牌的物理 ID 用于各自计分解释，没有复制实体牌或执行多次结算。

收齐之前不发布历史变更；收齐后结果和各次查询快照均不可变。只提供 `PASS` 的三家可以在构造时立即得到无声明结果，其中无役完成牌仍会正常触发同巡振听。

## 身份与重放边界

`Id` 由对局拥有者提供；同一小局每次舍牌必须使用不复用的非负 `serial`。窗口拒绝其他局／其他窗口、非响应座位、重复答复、未提供的动作或不同牌实例选择；拒绝不改变已收集状态。窗口关闭后任何再次提交都不会覆盖结果。

这是由权威单线程持有的普通 Java 状态对象，未来对局层须将当前窗口保存为唯一当前对象，并把真实连接玩家映射到座位后调用。它不能证明调用者网络身份，不能阻止错误的外部拥有者重建同一个局号／窗口号，也不是跨重启的结算幂等账本。本批没有响应超时策略、抢杠窗口、立直宣言成立、途中流局或新客户端按钮。

## 验证

新增 **5,224 个独立断言**，包含四种出牌座位 × 八种荣和选择集合 × 六种响应到达顺序的 192 个场景；另验证碰杠／吃／荣和竞争、放弃高优先级动作、赤牌选择、无役自动跳过、河底役、旧窗口与重复请求、物理牌冲突及不可变快照。聚合入口为 `RulesTests`，可用 `tools/Test-Rules.ps1` 脱离游戏运行；最终构建及服务端回归见 [VALIDATION.md](VALIDATION.md)。
