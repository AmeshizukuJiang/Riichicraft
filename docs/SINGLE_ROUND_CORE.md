# 独立四麻单局引擎

开发版本：`0.0.4-dev`。`FourPlayerRound` 已将牌形、役符、振听、摸打与鸣牌、立直、抢杠、翻宝和点数账本接成可独立运行的单局。核心只使用 Java 与项目的 `TileCatalog`，不引用 Minecraft、Fabric、网络、客户端类或真实时钟；现另由服务端、网络与界面适配层接入 Minecraft。玩家流程见 [SINGLE_ROUND.md](SINGLE_ROUND.md)，最终游戏运行与补强菜单后重跑证据见 [VALIDATION.md](VALIDATION.md)，不以本页离线结果代替游戏验收。

规则基线见 [FOUR_PLAYER_RULES.md](FOUR_PLAYER_RULES.md)，组件索引见 [RULES_CORE.md](RULES_CORE.md)。本页描述单局权威入口及单局批次证据；东风／半庄整场现由 [整场所有者](MATCHES.md)推进，三麻尚未实现。

## 当前状态与动作

`shuffled()` 接受固定种子，`ordered()` 接受完整的 136 枚物理牌排列；两者均要求四个不同的玩家 UUID、合法庄家／场风和守恒账本。四家物理座位固定，自风相对本局庄家计算。配牌后由引擎执行庄家首摸，初始活牌数为 69。

| 阶段 | 可接受的动作与去向 |
| --- | --- |
| `DRAWN_TURN` | 当前玩家选择确切物理弃牌、立直弃牌、自摸、暗杠／加杠或合资格的九种九牌；弃牌开舍牌响应，杠宣言开抢杠响应，自摸／九种终局 |
| `CALL_DISCARD` | 吃碰者按食替遮罩立即弃牌；没有普通摸牌、立直或自杠机会 |
| `DISCARD_RESPONSES` | 三家提交本窗口提供的荣和、具体吃碰明杠或跳过；收齐后统一裁决，再决定终局、立即弃牌、岭上或下家普通摸牌 |
| `KAN_RESPONSES` | 三家选择抢杠或跳过；被抢则终局，未被抢才正式移组、取消一发、处理本次翻宝与岭上 |
| `FINISHED` | 保存唯一终局结果，不再接受新的对局动作或重复支付 |

玩家没有荣和或鸣牌选项时自动跳过；有合法响应时允许明确跳过。引擎不内置倒计时、自动选牌、机器人或客户端动画。

## 身份、修订与稳定窗口

适配层必须从已经验证的连接取得 UUID，调用引擎时不能让客户端自行声称座位。引擎将 UUID 映射到四家；旁观者、错误小局、非当前玩家、过期修订、错误阶段和未提供的物理选择均被拒绝，拒绝不改变状态。

本人回合动作携带 `Command(roundId, revision)`，每次成功动作更新修订。普通舍牌与抢杠响应则使用 `DiscardResponseWindow.Id(roundId, serial)`：同一窗口中其他家已经响应，不会让本家的窗口失效。窗口号、小局号、响应者和具体选项仍逐一检查；重复响应不能被当成第二次有效选择。

这提供单个存活引擎实例中的动作裁决与防重放边界。跨小局 ID 的生成、进程重启后的恢复、线程调度和连接认证归适配／整场层；不能从本核心推断这些功能已经完成。

## 玩家视图与服务端秘密

`view(recipient)` 返回不可变快照。所有接收者可见四家身份、自风、暗手数量、声明组及来源、牌河与被鸣标记、点数、立直阶段、当前行动者、剩余活牌和已翻表指示牌。每名参局者仅取得自己的暗手、本人可见摸牌、振听历史与合法动作／响应选择；旁观者没有暗手或行动权限。

未翻表宝、里指示牌、牌山顺序和别家暗手不会进入正常玩家视图。终局中的计分解释用于公开赢家结果；临时和牌计算不把同一枚荣和牌复制进所有赢家的持牌。

`serverState()` 包含四家暗手、完整牌山、里宝、各家历史、杠状态和账本，只用于服务端诊断与测试。**不得将该类型或整份牌山直接序列化为客户端数据。** 原快照不随后续动作变化。

## 已接续的规则事件

本人真实普通摸牌或岭上摸牌才清同巡振听；吃碰及舍牌不清除。普通舍牌与加杠见逃按全部结构完成牌记录，暗杠仅国士参与；先应用响应前历史，再执行选中的鸣牌。被鸣走的舍牌仍保留在原主历史中。

立直弃牌先进入真实荣和响应；无人荣和后才扣棒入供托并成立，被吃碰仍成立但一发取消。引擎用本人首舍与全场鸣牌历史建立双立直、天和／地和及一发事实。海底／河底来自真实末张普通摸牌来源，岭上即使令活牌数归零也不会被冒充海底。

暗杠／加杠在抢杠响应结束前不成立；被抢不产生本次杠、岭上或新杠宝，保留原有有效一发。明／加杠延后翻宝、连续杠先翻前一次宝、多家第四杠的岭上自摸与弃牌荣和优先级，均接续已有 [杠状态组件](KAN_FLOW.md)。同一人四杠继续，全桌不允许第五杠。

## 流局、流满与包牌

这些精确分支已在 2026-10-16 获得用户直接确认，来源如实记录，不冒称新找到的官方逐例原文。

- 九种九牌只在未受任何成立吃碰杠打断的本人首摸选择；四风连打在第四张同风首舍先收荣和；四家立直在第四宣言无人荣和后先扣棒成立，再流局。多人第四杠仍先受理岭上自摸及随后的弃牌荣和。途中流局不移点，供托保留。
- 最后弃牌无人荣和后，以 `RoundDrawRules.tenpai()` 判形式听牌：无役、振听、外部待牌已见尽不影响；连同声明组自持四枚、只能求第五枚不算听。一般荒牌在听／不听双方之间分配总计 3,000，全部听或全部不听不支付。
- 流局满贯要求门清（暗杠允许）、牌河非空且全为幺九、本人舍牌无被他家鸣走。多人各自按满贯自摸收款，其他流满者仍支付；替代不听罚符，不加本场费，不领取供托。途中流局不检查流满。
- 包牌从真实鸣牌来源建立：已有两种三元／三种风的声明刻杠，含先前声明暗杠，最后一种由他家供碰／大明杠才记录提供者；未声明暗刻不算，最后自行暗杠不新增，加杠沿用原碰来源。结算只在对应大三元／大四喜实际出现时应用组件责任，不从最终役名反推提供者。

`RoundLedger.settleExhaustive()` 和 `settleAbortive()` 返回关闭的账本与逐项收据，保留供托；和牌仍按最近赢家领取多响本场／供托。终局输出 `dealerContinues`：和牌看赢家是否含庄家，荒牌／流满看庄家是否听牌，途中流局为连庄。它没有自行开下一局或递增本场。

## 每步守恒

每次成功动作后，`assertConservation()` 审计四家暗手与声明组、未被鸣走河牌、活牌、王牌，以及被抢杠单独移出的和牌张：恰好占有全部 136 枚不同的物理 ID。被鸣走的牌只在声明组计一次；多人荣和共用的和牌张只计一次。王牌始终 14 枚，已成立杠的归属、声明组、岭上消耗和手牌数量必须与阶段一致。

账本同时要求四家点数加供托池为100,000，且终局阶段与账本关闭状态相符。允许结算后负分，不截断得点；击飞、整场目标点与最终排名由`MatchRules`／`FourPlayerMatch`在完整支付后处理。

## 离线验证证据与范围

此前十三套组件测试共 353,477 个断言。本批三套分别以项目内固定 JDK 独立运行取得：

| 套件 | 断言与实际覆盖 |
| --- | --- |
| `RoundDrawTests` | 103,218；16 种听牌集合 × 16 种流满集合 × 4 庄位 × 3 账本，含负分、既有供托、互付满贯和回执重建；真实手牌资格、全部声明刻杠组合的包牌边界及非法输入 |
| `FourPlayerRoundTests` | 1,119,055；64 个固定种子完整牌局，实际均为荒牌，259 次鸣牌、8 次杠、0 次立直、0 次和牌；逐动作检查身份、阶段、窗口、视图、牌与点数守恒 |
| `RoundScenarioTests` | 627；14 个预先安排的完整 136 枚物理墙，经公开动作入口实际完成双响／三响、立直被荣和取消、吃碰食替、国士抢暗杠、四暗杠岭上、四立直及其荣和优先、宣言牌被鸣、四风、大三元包牌、流满与多人第四杠的两个实际终局分支 |

新增两份多人第四杠确定墙实际执行第四次岭上与随后弃牌：无人荣和才流局；舍东被庄家双倍四暗刻单骑荣和时，由出牌者支付 96,000，荣和优先于流局。两条轨迹都保留恰好四次岭上、五张已翻表宝和 62 枚活牌，没有提前流局或多摸下一张。

合计十六套 **1,576,377 个断言**。随机轨迹没有出现和牌／立直，不能把“支持尝试这些动作”当作覆盖；对应实际场景由确定墙测试补充。统一入口重跑、资源检查、构建以及 Minecraft 服务端／客户端结果均以 [VALIDATION.md](VALIDATION.md) 的已执行记录为准。

四人单局批次的35项服务端测试、真实TCP鼠标碰牌／立即弃牌和终局重连均通过；之后整场批次扩至38项，实际完成东风／半庄及局间重连，见 [MATCHES.md](MATCHES.md)与验证记录。TCP另三席是原生服务端内存夹具，并非四真实客户端。三麻、跨重启恢复与超时仍未实现；自动化不代表人工视觉与长期操作手感验收。
