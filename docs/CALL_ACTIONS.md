# 独立鸣牌动作与牌山

版本：`0.0.4-dev`。本批实现普通舍牌下吃、碰、大明杠的选项生成和不可变手牌执行，并实现独立的配牌／活牌山／王牌。它们可与既有响应窗口组合，但尚未组成完整对局，也未接入 Minecraft。

## 已确认边界与来源

2026-10-16 用户明确确认：吃／碰后不能立即打被鸣牌的同种牌；两端吃也不能打与原两张手牌构成另一顺子的牌。例如 23 吃 1 后禁 1／4，78 吃 9 后禁 6／9；24 吃 3 只禁 3。赤牌与普通牌同种处理。若剩下的牌全被食替限制，该鸣牌不可选。

同次确认还规定：海底摸出后的舍牌只能荣和，不能再吃碰杠；活牌山为空时不能开杠。这些具体边界按用户确认实现；官方段位规则的“禁止食替”概括仍保留为官方来源，不将用户确认的完整例子冒充官方原文。普通规则和其他未决窗口见 [FOUR_PLAYER_RULES.md](FOUR_PLAYER_RULES.md)。

## `CallActions` 契约

`options(hand, discardedTileId, context)` 接收响应前的十三张结构手牌、准确物理舍牌，以及出牌／响应座位、剩余活牌数、全桌已成立杠数和本人已成立立直事实，返回所有准确的 `DiscardResponseWindow.Call` 组合。

- 吃仅限出牌者之后一家，不能跨花色、用字牌或拆固定声明组；碰／大明杠可来自其他三家。
- 两枚持牌组成吃／碰，三枚组成大明杠；多个赤／非赤或相同牌副本的选择都保留，不按牌种合并掉物理选择。
- 已成立立直／双立直禁止三种鸣牌；无需已有役，允许后付。没有活牌时均不提供；已有四杠不再提供第五杠。已有四组固定声明组不能再新增第五组。
- 输入检查暗手／声明组／舍牌物理不重叠、牌数以及全桌杠数至少包含本人已成立杠；开放手牌不能声称已立直。
- 吃碰选项必须留下至少一种非食替的即时弃牌。限制只作用于这次鸣牌后的立即出牌，不改写永久舍牌规则。

`apply()` 用当前同一份真实事实重新生成选项，只接受其中一个完整物理选择；拒绝不会修改输入。它移出准确的持牌、加入包含原舍牌的新 `Meld`，保留原所有声明组，输出手牌、鸣牌者／提供者、原舍牌以及允许立即弃牌的物理 ID 集合。

吃／碰结果为十四张结构状态，须直接弃牌，不能先普通摸牌。大明杠结果为十三张结构状态，`needsReplacementDraw()` 为真，暂时没有可弃牌选项；须在杠真正成立后从王牌摸岭上，再进入弃牌。不能把十三张数量解释为缺少牌组或直接推进下家摸牌。

未来对局拥有者须先确定真实行动阶段、连接玩家到座位的映射，收齐舍牌响应并采用选中的唯一鸣牌，再调用 `apply()`；客户端不能提交自造的 `Context` 或已执行手牌。响应窗口的三家见逃历史也须一并应用；吃碰本身不会清除同巡振听。鸣走的河牌由拥有者标记，不能同时继续作为可取走的实体牌；历史舍牌种类仍保留。提供者信息供未来牌河与包牌追踪使用，本批未实现包牌判定。

## `RoundWall` 契约

`shuffled(seed)` 使用固定 Fisher–Yates 顺序；`deal(orderedTiles)` 接受全部 136 个不同且合法的物理 ID。两者返回庄家相对座位的四份十三张手牌及剩余 70 枚活牌、14 枚王牌；庄家首摸由调用方执行一次 `drawLive()`，之后活牌剩 69 枚。

逻辑顺序为配牌 52 枚、活牌 70 枚，最后依次是四枚岭上牌和五对交错表／里指示牌；这定义可复现的核心牌序，不声称已实现实体堆牌、掷骰或开门动画。`drawLive()` 返回普通牌源 `LIVE`，只在这次确为活牌末张时返回 `LAST_LIVE`。

`drawReplacement()` 最多四次，还要求至少一枚活牌可补入王牌：取一枚尚未使用的岭上牌，将当前活牌末尾移入该槽，活牌数减一，王牌始终 14 枚，表里指示牌不移动。即使此次补牌令活牌数归零，其来源仍是 `RINSHAN`，不会被误标为普通海底自摸。方法返回新状态，旧快照不变；空牌山或无岭上牌时拒绝摸牌。

`doraIndicators(count)`／`uraIndicators(count)` 只读取 1～5 对已布置槽位，**不证明这些槽位已获合法翻开**。立即／延迟翻杠宝、抢杠和第四杠终局的时序归未来对局状态机；为允许在暗杠摸岭上前翻牌，牌山不以已摸岭上的次数推测合法翻牌数。整个对象、未翻表宝和全部里宝是服务端私有数据；不能将其列表直接广播给玩家。

## 验证与尚未接入的部分

`CallActionsTests` 通过 43,462 个断言：所有花色、顺子位置、四种出牌座位和三种相对位置；2×3 物理吃牌组合；34 种牌／四种舍牌副本的碰杠选择；赤牌保留、现物／筋食替、无合法弃牌、末巡、立直、第四／第五杠和固定组限制。350 个固定种子 × 三名响应者的候选集合，与枚举所有持牌二／三元子集的独立参考对照；生成选项亦通过既有多人响应窗口，正确选择碰后执行。

`RoundWallTests` 通过 101,983 个断言：精确配牌顺序、种子可复现、四次岭上及尾牌转移、末张普通／岭上来源、非法牌序与不可变快照；240 个固定种子的混合摸牌进程逐步审计完整 136 枚身份与 14 枚王牌。脚本明杠场景组合了真实配牌、普通摸牌、鸣牌执行、岭上补牌和十四张结构状态，保持整副牌守恒。

上述七套及后续立直／弃牌／账本套件均由 `tools/Test-Rules.ps1` 和 Gradle `rulesTest` 运行；新组件见 [RIICHI_AND_LEDGER.md](RIICHI_AND_LEDGER.md)。构建与原有游戏回归证据见 [VALIDATION.md](VALIDATION.md)。当前没有暗杠／加杠动作执行、抢杠窗口、流局、责任触发历史或整场轮转，也没有新客户端按钮。用户已授权在核心闭环可验证时直接接入游戏，无需再确认接入时机。
