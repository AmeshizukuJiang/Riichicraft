# 存档协调职责整理

日期：2026-10-20，开发版`0.0.20-dev`，基线`9a1291f`，分支`codex/persistence-coordination`。

## 本次目标

用户明确开发阶段不把历史测试版存档兼容作为维护目标。本步提取当前实现的保存协调，降低大厅服务中分散保存状态造成的出错风险。没有新增迁移分支、格式版本、依赖、保存触发点或玩法。

## 职责边界

- `TablePersistenceCoordinator`拥有保存路径与写入器、待保存标记、写入失败／全文件损坏／运行态已脱离标记，以及需要原样保留的损坏核心记录。先完整校验名册再允许发布恢复座位；合并健康与保留记录、排序并调用原原子写入器。
- `LobbyService`继续拥有核心、桌子与玩家，将当前已接受状态转换为保存记录，安装恢复对象并向参与者发送错误提示。活动局暂停、局间清票、椅侧及身份恢复继续走原流程。
- `TableArchiveStore`继续负责受限二进制读取、完整性校验及原子替换，规则核心仍负责本版牌局重放。两者均未增加兼容或迁移逻辑。

保存结果显式分为成功、跳过与本次失败，避免将损坏或停服后的拒写当作成功，也避免每次原生保存都重复通知。只有确实需要检查点时才调用记录提供者；暂时失败保留待保存标记，重试重新读取最新已接受状态，不缓存旧快照。运行态清理前先保存并脱离，后续原生保存不能将空内存覆盖原文件。
